# Rules for agents working in this repo

This repo teaches the full pipeline for a short vertical video with an AI character, driven by Claude Code, in seven steps: idea, character, song or voice, animation, timings, a motion-graphics edit written as HTML + GSAP, and a render to MP4 with HyperFrames (https://github.com/heygen-com/hyperframes, Apache-2.0). There are three worked examples, and all three skip steps 2 to 4 (character, song, animation) and use existing footage:

- `examples/wing-it`, the hero (the README GIF and our X post): 30 seconds of Blender Studio's open movie WING IT! (CC BY 4.0, from Wikimedia Commons), cut at its 12 shot changes into a 9:16 video with one crop per shot (`shots.json`), with the film's own sound. The idea was a one-liner, a checklist that the flight ignores. Its timings are story events read by eye from frames (`events.json`); there are no words and no beat grid.
- `examples/spin-count`: a Pixabay stock clip of an animated 3D boy, labelled AI generated on its page, and a Pixabay music track. The idea was a one-liner, count his spins. Its timings are ten spin marks read by eye from frames and a beat grid from `npx hyperframes beats`; there are no lyrics and no `transcript.json`.
- `examples/handwash-song`: CDC's public-domain "Happy Handwashing Song" cartoon. The idea was a one-liner, count the 20 seconds the song takes. Its timings are Whisper word timestamps aligned to `lyrics.txt`.

All three run steps 5 to 7 in full. The generation steps (1 to 4) are documented from provider docs and have not been run by the author; never present them as tested. `CLAUDE.md` and `AGENTS.md` have the same content; change both or neither.

## Commands

Run from the repo root. Set the telemetry variable in every shell that runs HyperFrames.

```bash
export HYPERFRAMES_NO_TELEMETRY=1          # PowerShell: $env:HYPERFRAMES_NO_TELEMETRY = "1"
npx hyperframes@0.8.143 browser ensure     # once per machine (Chrome Headless Shell)
npx hyperframes@0.8.143 doctor             # check dependencies

# handwash-song
node scripts/fetch-assets.mjs examples/handwash-song    # download + preprocess + probe
node scripts/align-lyrics.mjs examples/handwash-song    # ASR words + lyrics.txt -> transcript.json
node scripts/build.mjs examples/handwash-song           # template + transcript -> index.html
npx hyperframes@0.8.143 lint examples/handwash-song
npx hyperframes@0.8.143 snapshot examples/handwash-song --at 3.6,14.0,26.5 --describe false
npm run render                                          # delivery render + edge fix -> renders/handwash-song.mp4

# wing-it
node scripts/fetch-wing-assets.mjs examples/wing-it    # download from Commons + cut by shots.json + probe
node scripts/build.mjs examples/wing-it                 # no placeholder, no transcript: copies the template
npx hyperframes@0.8.143 lint examples/wing-it
npx hyperframes@0.8.143 snapshot examples/wing-it --at 0,0.05,3.6,11,22.2,26.3,29.1,31.6 --no-end --describe false
npm run render:wing                                     # delivery render + edge fix -> renders/wing-it.mp4

# spin-count
node scripts/fetch-spin-assets.mjs examples/spin-count  # download from Pixabay + preprocess + probe
node scripts/build.mjs examples/spin-count              # no placeholder, no transcript: copies the template
npx hyperframes@0.8.143 lint examples/spin-count
npx hyperframes@0.8.143 snapshot examples/spin-count --at 0.8,2.6,8.9,20.6 --describe false
npx hyperframes@0.8.143 beats examples/spin-count       # rewrites beats/assets/music_cut.mp3.json
npm run render:spin                                     # delivery render + edge fix -> renders/spin.mp4

# any example
node scripts/probe.mjs <files...>                       # duration, fps, sample rate, channels
npx hyperframes@0.8.143 render <exampleDir> -q draft -o <exampleDir>/renders/draft.raw.mp4
node scripts/fix-right-edge.mjs <exampleDir>/renders/draft.raw.mp4 <exampleDir>/renders/draft.mp4
node scripts/framemd5-diff.mjs a.mp4 b.mp4              # frame-by-frame equality
```

## Hard rules

1. **Edit the template.** `build/index.template.htm` is the source of truth. After every edit run `node scripts/build.mjs <exampleDir>`. With a `/*TRANSCRIPT*/[]` placeholder and a `transcript.json` (handwash-song) it inlines the words and writes `index.html`; with neither (spin-count) it copies the template to `index.html` byte for byte. Never hand-edit `index.html`; the next build overwrites it. `node scripts/build.mjs <exampleDir> --check` exits 1 when `index.html` is out of date. Keep the `.htm` extension: `npx hyperframes@0.8.143 preview` (Studio) writes `data-hf-id` attributes into every `*.html` file in the project folder that contains `data-composition-id`, and `transcribe` patches `*.html` files too. After any preview, `index.html` is modified: run `node scripts/build.mjs <exampleDir>` to regenerate it (or `git checkout -- <exampleDir>/index.html`) and review `git diff` before you commit. Stop a background preview with `npx hyperframes@0.8.143 preview <exampleDir> --stop`.
2. **Timings come from data, never from guesses.** In handwash-song, every event tied to a sung word is keyed to `TRANSCRIPT[i].start` or `.end`; `LINES` and `SLOTS` hold word indices, never seconds. In spin-count, every spin event is keyed to `SPINS[i]` and the title pulse to `BEAT0` and `BEAT`. `SPINS` holds source times divided by the 0.85 slow-down and must match `spins.json`; change both together, and check every new mark with a frame grab (docs/06, "Timings without words"). In wing-it, the story events are seconds in the cut footage, in `ITEMS`, `GADGETS` and the cue calls of the template, and must match `events.json`; change both together and check every new event with a frame grab (docs/06, "Story events"). The cut itself lives in `shots.json`: a change there changes the footage and moves every event after it. Literal seconds are allowed only for the intro before the first event, short offsets relative to an event (lead-ins and holds), the end of the footage (`VIDEO_END`), and the total duration, which must equal the root `data-duration`.
3. **`transcript.json` is produced by `scripts/align-lyrics.mjs`.** Text comes from `lyrics.txt`, times come from the ASR output. If a time is wrong, fix the input and re-run the script. If you must hand-correct a word, say which word and why in your reply and in the commit message.
4. **Never run `npx hyperframes transcribe` with `--dir` pointing at an example folder.** It writes its own `transcript.json` into that folder (overwriting the aligned one) and rewrites any `const TRANSCRIPT = [...]` it finds in the folder's HTML with the raw, unaligned words. Point `--dir` at a scratch folder. (Checked with 0.8.143 by importing `whisper_verbose.json`: `index.html` was rewritten with 39 raw words; the template, which holds a placeholder, was left alone.) `npx hyperframes@0.8.143 beats <exampleDir>` is safe: it writes only `beats/<audio>.json` (checked on spin-count).
5. **Never commit media.** No `*.mp4`, `*.webm`, `*.mp3`, `*.wav`, generated images, `gsap.min.js`, `renders/`, `snapshots/`, and nothing under `assets/source/`. Media is fetched by `scripts/fetch-assets.mjs`, `scripts/fetch-spin-assets.mjs` or `scripts/fetch-wing-assets.mjs`, or generated on the user's account. This applies to the CDC source, the Pixabay clip and track, the WING IT! film (CC BY 4.0 would allow sharing it; the rule still holds), and everything derived from them, except the preview images in `docs/img/`. Full renders are published as GitHub release assets, never committed. Contact sheets and frame grabs go under `assets/` (for example `assets/frames/`), which `.gitignore` covers.
6. **Probe every input and every output** with `node scripts/probe.mjs` (or ffprobe): duration, fps, frame count, audio sample rate, channels. Never assume 44.1 kHz. An earlier in-house tool labeled 48 kHz samples as 44.1 kHz and the audio drifted out of sync. HyperFrames writes 48 kHz AAC even when the input MP3 is 44.1 kHz; that is expected.
7. **Lint before any render.** `npx hyperframes@0.8.143 lint <exampleDir>` must report 0 errors. It reports `nested_structure_needs_subcomposition` warnings, 2 on handwash-song and 1 each on spin-count and wing-it, harmless for a single-file composition. If the compiler warns about sparse keyframes in a video, re-encode it with a keyframe every second (`-g 30 -keyint_min 30` at 30 fps). Encode every video at a width that is a multiple of 16 (handwash-song's `cat.mp4` is 1088x672): HyperFrames extracts video frames through a yuv420p to gbrp conversion that, with ffmpeg 8.1.2, blacks out every column after the last multiple of 16. spin-count's `boy.mp4` and wing-it's `wing_v.mp4` are 1080 wide to match the renders that were published; as full-frame footage their band falls on the render's own strip at x 1072 to 1079 and the edge fix covers it. Use 1088 for new full-frame footage.
8. **Stop before rendering.** Passing checks is not a reason to render. Show snapshots, wait for the human, then render a draft, wait again, then render delivery. Delivery renders on the reference machine: 64.6 s for the 30.8 s handwash-song with draw-element capture (109 to 133 s when an earlier template forced the screenshot fallback), 94 s for the 21.5 s spin-count (screenshot capture), 1 min 43.3 s for the 32.5 s wing-it (draw-element capture), plus 36 to 42 s for the right-edge fix on full-frame footage (see each example's README).
9. **Fix the right edge after every render.** Every render on the reference machine has an 8 px black strip at x 1072 to 1079. It is an FFmpeg 8.1.2 bug that HyperFrames triggers: ffmpeg's x86 SIMD conversion from yuv420p, yuvj420p or yuv422p to gbrp blacks out every column after the last multiple of 16, and HyperFrames 0.8.143 converts every captured frame that way (repro: `ffmpeg -f lavfi -i "color=c=white:s=1080x64,format=yuv420p" -frames:v 1 -vf format=gbrp out.png`; clean with `-cpuflags 0`). Seen with the gyan.dev Windows build; other builds and OSes untested. Render to `<name>.raw.mp4`, then run `node scripts/fix-right-edge.mjs <name>.raw.mp4 <name>.mp4` (with no strip it copies the file unchanged). Its default `--mode auto` measures the two columns left of the strip: a flat page (handwash-song, 4 luma levels of spread) gets a flat fill in the page color, footage or a gradient (spin-count, 68 to 76 levels; wing-it, 79 to 136) gets `smear`, which repeats column 1071. A flat fill on a gradient shows a seam; smear on a flat page stretches anything that touches column 1071 into a bar. Report which mode it picked. Compare raw renders, never fixed ones, in a determinism check: the fix re-encodes. Make previews (GIFs, stills) from fixed files; for handwash-song, from before 25.17 s, where the CDC end card with logos starts.
10. **Pin HyperFrames.** Always call `npx hyperframes@0.8.143`. Bare `npx hyperframes` resolves to whatever is latest, and the project releases almost daily. Upgrading means: change the version everywhere, re-run lint, compare snapshots, re-run the framemd5 determinism check, check the right edge, update measured numbers in the docs. After any ffmpeg change, run the one-line repro from rule 9 again.
11. **Telemetry and outbound calls.** HyperFrames telemetry is on by default; keep `HYPERFRAMES_NO_TELEMETRY=1` set. `snapshot` sends frames to Gemini when `GEMINI_API_KEY` is set, so always pass `--describe false`. Do not run `npx hyperframes feedback` or `npx hyperframes usage` unless the human asks (`usage` reads Claude Code credentials).
12. **Paid generation.** Never call a paid model (image, music, voice, video) without the human's OK for that specific batch. State the model, provider, quantity and list price first; log every paid call in the project's `costs.csv`, rejected takes included. The human installs and logs into any generation CLI or MCP server.
13. **Secrets.** `GROQ_API_KEY`, `FAL_KEY` and any other key are read from the environment. Never print them, never write them to a file, never paste them into a prompt, never commit `.env`.

## Composition contract (HyperFrames)

- One `gsap.timeline({ paused: true })`, registered synchronously as `window.__timelines["<data-composition-id>"]`.
- No `Math.random` (use a seeded PRNG), `Date.now`, `performance.now`, `requestAnimationFrame`, `setTimeout`, `setInterval`, or `fetch`. HyperFrames seeks every frame; anything that reads a clock breaks determinism.
- Media playback is driven by `data-start`, `data-duration` and `data-media-start`. Never play, pause or seek media from script.
- Every `<video>` is `muted` (or has `data-has-audio="true"`). Every `<audio>` has an `id`, or the render is silent.
- Do not center with `transform: translate(-50%,-50%)` on an element GSAP moves; use flex, `left/top`, or `xPercent/yPercent`.
- Do not tween `visibility`, `display` or `autoAlpha` on `.clip` elements; animate a child.
- Do not measure the DOM inside tweens or callbacks; compute layout once at build time.
- Do not write to the DOM from `onUpdate`, `onComplete` or any other timeline callback; tween a property instead (a number on screen is the element's `textContent` with `snap: { textContent: 1 }`). The handwash example's first counter was written from `onUpdate`, which made HyperFrames' draw-element self-check fail at frame 693 and forced the slower screenshot capture. wing-it's altitude counter still writes `#alt-num` from `onUpdate`; it is kept as rendered for the posted video, and its render passed the check anyway. Do not copy it. On a failed check HyperFrames leaves `hf-de-verify-fail-*/frame-N-truth.jpg` and `frame-N-de.jpg` in the system temp folder; compare them, then delete the folders.
- A `fromTo` applies its from-state when the timeline is built, not at its start time. Make every from-state of an element that should not be visible yet hidden (`opacity: 0` or `scale: 0`), and never `fromTo` a property that an earlier intro tween animates from a hidden state: use `to`, or pass `immediateRender: false` (wing-it's chip and counter bumps). spin-count hit both: stickers with `opacity: 1` in the from-state sat on screen from frame 0, and a pill bump `fromTo({ scale: 1 })` showed all ten pills at full size for the first 4 frames of the posted render.
- GSAP 3.14.2 loads from `assets/gsap.min.js`. Fonts are Poppins and Inter; HyperFrames fetches both from Google Fonts on first compile and caches them. Name fonts with `font-family` (plus `font-weight`, `font-size`), never only in the `font:` shorthand: HyperFrames 0.8.143 neither fetches nor lints a family named that way, and the text falls back to the system font. The compile log should say `Injected deterministic @font-face rules for 2 requested font families`.
- The root `data-duration` is read before scripts run. Change it in the HTML, never from JS.

## After a change, before you report done

1. `node scripts/build.mjs <exampleDir>` (and `--check` on the examples you did not touch)
2. `npx hyperframes@0.8.143 lint <exampleDir>`: 0 errors
3. `npx hyperframes@0.8.143 snapshot <exampleDir> --at <times> --describe false`, then look at `snapshots/contact-sheet.jpg`
4. If you changed timing logic: in handwash-song, snapshot every lyric line start + 0.15 s and confirm the right word is lit; in spin-count, snapshot each spin mark + 0.3 s and confirm the right number is on screen; in wing-it, snapshot each checklist event and gadget + 0.2 s and confirm the chip, the score and the counter; in both, snapshot 0 and 0.05 s to confirm nothing shows before its intro
5. If you changed a doc, a prompt or a heading: `node scripts/check-links.mjs` (or `npm run check-links`) must report that every relative link in the repo's Markdown files resolves, anchors and `#L` line ranges included
6. Say what you checked and what you did not

## Writing style for docs and prompts

Plain, direct English. No em-dashes, no emojis, no marketing words. Every number must be measured on this repo or cited with a URL; mark anything unverified as unverified, and anything about the generation steps as not run by us. Never cite a view count you did not measure yourself.

Everything is written from the author's own perspective. Do not mention other creators or social accounts anywhere in the repo: no handles, no posts or links to them, no quotes, numbers or view counts of theirs, no credit lines for ideas. Write a method so that it stands on its own. Vendors and tools (HyperFrames/HeyGen, Google, OpenAI, ElevenLabs, fal, Picsart, Higgsfield, GSAP), platform policies, and the credits that a media license requires (Blender Foundation, CDC, the Pixabay uploaders) are fine.
